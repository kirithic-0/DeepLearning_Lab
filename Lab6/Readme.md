# RNN, LSTM and GRU for Sequence Learning and Video Understanding — Human Activity Recognition

CS3807 – Deep Learning Laboratory, Experiment 6 - End-to-End Study of RNN, LSTM and GRU for Sequence Learning and Video Understanding

A TensorFlow/Keras study that implements and compares a Vanilla RNN, an LSTM and a GRU on the UCI Human Activity Recognition raw inertial signals, then extends the same recurrent idea to video understanding with a frozen MobileNetV2 feature extractor on UCF101 clips, and closes with an encoder–decoder sequence-to-sequence reversal task.

## Overview

This project covers the full sequence-learning pipeline end to end:

- Raw inertial signal loading - the nine raw HAR channels are arranged into `(N, 128, 9)` tensors, with a balanced 2,400-window subset (400 per class) drawn from the full training partition
- Backpropagation Through Time - a small numerical exercise checking hand-computed hidden states against the program, plus the vanishing/exploding gradient discussion
- Identical classifier across RNN / LSTM / GRU - only the recurrent layer changes (SimpleRNN, LSTM, GRU), so the comparison is fully controlled
- Training and validation curves, macro-averaged precision/recall/F1, confusion matrices, parameter counts and training times for all three models
- Effect of sequence length, repeating the study for `T` in {32, 64, 128}
- Video understanding - 10 frames sampled per clip at 224x224x3, a frozen MobileNetV2 (head removed, global average pooling) producing 1280-dim features, then an LSTM/GRU classifier over the `(B, 10, 1280)` feature sequence
- Sequence-to-sequence learning - an encoder–decoder that reverses short integer sequences, reported with token accuracy vs sequence accuracy
- Seven additional exercises (recurrent-unit sweep, GRU vs LSTM at equal units, a stacked second layer, bidirectional vs unidirectional LSTM, sequence-length vs cost, video LSTM vs GRU on identical features, and a variable output-length seq2seq)

## Results

### Recurrent models on HAR (test set)

| Model | Accuracy | Macro F1 | Parameters | Train time |
|---|---|---|---|---|
| Vanilla RNN | 76.67% | 76.59% | 1,974 | ~106 s |
| LSTM | 94.17% | 94.15% | 6,006 | ~14 s |
| GRU | 95.00% | 94.98% | 4,758 | ~14 s |

The GRU gives the best F1 at fewer parameters than the LSTM, while the Vanilla RNN trails both and trains far more slowly because its recurrence does not use the cuDNN fused kernel.

### Video understanding on UCF101 (frozen MobileNetV2 + recurrent)

| Model | Accuracy | Macro F1 | Parameters |
|---|---|---|---|
| CNN-LSTM | 99.09% | 99.07% | 168,196 |
| CNN-GRU | 97.27% | 97.26% | 126,276 |

Four action classes (Basketball, Biking, TennisSwing, WalkingWithDog), 110 clips per class, 10 frames per clip. Both recurrent heads sit on the same cached 1280-dim frame features, so the only difference is the recurrent layer.

### Sequence-to-sequence reversal

| Measure | Value |
|---|---|
| Token accuracy | 99.30% |
| Sequence accuracy | 96.50% |
| Final validation loss | 0.0249 |

Sequence accuracy is stricter than token accuracy - a single wrong token makes the whole sequence wrong - so it is always at or below the token accuracy.

> Numbers are from a local run on this machine and are reproduced deterministically from a fixed seed; cuDNN's fused recurrent kernels can still shift them by a point or two between machines.

## Datasets

This experiment uses two datasets.

### 1. UCI Human Activity Recognition Using Smartphones (primary)

Downloads automatically the first time the notebook runs - the setup cell fetches the archive from the UCI repository and unpacks it into `HAR/`.

- 7,352 training and 2,947 test windows, six activities (WALKING, WALKING_UPSTAIRS, WALKING_DOWNSTAIRS, SITTING, STANDING, LAYING)
- The **raw inertial signals** are used (not the precomputed 561-feature vectors): 3-axis body acceleration, 3-axis gyroscope and 3-axis total acceleration give nine channels, 128 time steps per window
- A balanced 2,400-window subset (400 per class) is split 70/15/15 into train/validation/test
- Official page: https://archive.ics.uci.edu/dataset/240/human+activity+recognition+using+smartphones

### 2. UCF101 action recognition (video section)

Unlike the HAR dataset, UCF101 is **not** downloaded automatically - the full archive is a ~6.5 GB `.rar` and is impractical to fetch inside the notebook. Download it once, extract only the four class folders used here, and place them so the notebook's relative glob resolves:

```
UCF101_data/
└── UCF-101/
    ├── Basketball/       *.avi
    ├── Biking/           *.avi
    ├── TennisSwing/      *.avi
    └── WalkingWithDog/   *.avi
```

The video cell reads clips via `glob("UCF101_data/UCF-101/<Class>/*.avi")`, samples 10 frames per clip with OpenCV, and skips nothing extra - no `unrar` and no `apt-get` are required once the folders above exist. Jupyter must run with its working directory at the repository root so the relative path resolves.

- Official page: https://www.crcv.ucf.edu/data/UCF101.php

## Getting Started

### 1. Clone the repository

```
git clone https://github.com/<your-username>/<your-repo-name>.git
cd <your-repo-name>
```

### 2. Set up a Python 3.10 virtual environment

TensorFlow only has native GPU support on Windows through version 2.10, which requires Python 3.10 specifically. If you're on Linux, WSL2, or Mac, any recent Python 3.9+ works fine with a normal current TensorFlow install instead - drop the version pin in `Lab6_requirements.txt`.

```
py -3.10 -m venv venv
venv\Scripts\Activate.ps1     # Windows PowerShell
source venv/bin/activate      # Linux / Mac / WSL2
```

### 3. Install dependencies

```
pip install -r Lab6_requirements.txt
```

On native Windows, using the GPU also needs CUDA Toolkit 11.2 and cuDNN 8.1.1 installed separately (TensorFlow still runs on CPU without them, just slower). Check `tf.config.list_physical_devices('GPU')` after installing to confirm it's detected.

### 4. Run the notebook

Register the venv as a Jupyter kernel first if it isn't already available in your editor:

```
python -m ipykernel install --user --name lab6-env --display-name "Python 3.10 (TF 2.10 GPU)"
```

The HAR dataset downloads automatically; make sure the UCF101 folders described above are in place before running the video section. Open the notebook locally in Jupyter or VS Code and run all cells top to bottom.

A GPU is recommended for the MobileNetV2 feature extraction over the UCF101 clips; the HAR recurrent models and the seq2seq task are small and run quickly even on CPU.
